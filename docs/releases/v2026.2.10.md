## VCS review and jj adaptations

- F4 opens the selected source from both the jj working-copy tree and history's
  changed-file tree. Deleted files remain closed; this does not request a Git diff.
- Added/deleted jj files use the shared full-width, one-sided diff viewer. The
  backend explicitly reports absent sides; an empty existing file remains distinct
  from an absent file. Historical text stays immutable and working-copy text stays
  editable where appropriate.
- The shared Show Diff in New Window action works for jj diff inputs. Native window
  launch data retains jj Blame revision identities and absent-side metadata rather
  than losing them at the IPC boundary. An unqualified jj path never becomes a Git
  HEAD/index diff. New-window identity includes the immutable revision identity.
- Shared pane alignment, divider-side line numbers and smooth difference scrolling
  are inherited. Filtered graph-lane compaction is shared with the jj graph.
- Upstream's case-only rename handling and unreadable-directory Git status fallback
  remain Git-specific; jj already delegates status and revision paths to jj itself.
  Git agent-task worktree acceptance/rollback, Update Info and live branch labels
  on recent projects are not mapped to
  jj bookmarks or change IDs.
- Repository discovery starts in Restricted Mode for jj as well as Git, following
  upstream's new default. The project trust gate enables execution; operations on
  a verified secondary jj workspace inherit the explicit parent operation's trust.
